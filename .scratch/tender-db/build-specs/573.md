## 1. Decisions (made here, with reasons)

**D573-1. R0d is decided where R1's bars are met: after D4 and S1, before the window.**
- The new branch sits right after `let rule = …` (head_election.rs:858–864). It fires only when `rule == R1` and
  the head is a dropped-accent form of a spelling of the elected cluster `&clusters[tied[0]]`.
- So R0d is a subset of R1 elections. The decision says exactly this: "elect S's cluster only when it is the unique
  top and passes R1's bars (T·20 ≥ V·11, T ≥ 3, T ≥ 2H)". Every R1 election, whether a change or a hold, is listed
  in plan 2653 (`held` not truncated, `planned` not truncated). That makes the re-plan's R0d set predictable from
  data on disk.
- `573-port.py` run over plan 2653 gives exactly the decided 15 (296 mention rows). No keep can become R0d.
- D4 is asked before R0d. It cannot fire here: the trigger requires an all-ASCII head with an ASCII letter (so its
  script is Latin), and the elected cluster's lead spelling is Latin in all 15.
- The alternative was to put R0d beside R0, before D4 and S1. That would need its own copy of R1's bars and would
  let unlisted D4 keeps join. Rejected.

**D573-2. The trigger is a pure store fn, `head_dropped_accent(head, spelling)`, not a new `HeadElectFns` field.**
- It needs no ingest function: it reads only chars, ASCII and whitespace.
- A new field would touch every `HeadElectFns` literal: the app's `head_elect_fns`, the store test `FNS`, the
  integration `FNS`, and the struct-update literals in tests.
- The wet pre-pass re-elects with the same code, so the dry plan and the wet run agree by construction.

**D573-3. The letter test is `char::is_alphabetic` on non-ASCII chars, and the case compare is
`eq_ignore_ascii_case`.**
- This is size.md's char-level test, which the decision adopted: the spelling with every non-ASCII char deleted and
  whitespace collapsed equals the head, case-folded. Two guards follow: (a) a word that keeps an ASCII letter lost a
  letter; (b) no deleted word was made only of 2 or more non-ASCII letters.
- The stripped spelling is all ASCII. So `eq_ignore_ascii_case` equals Python's `casefold` compare, and a head with
  any non-ASCII char never matches.
- Python's `size.py` also counted combining marks (Unicode category M) as lost letters; Rust's `is_alphabetic` does
  not. A head that lost only combining marks is the diacritic-folded spelling, which `head_vote_key` puts in the
  same cluster, so it never meets "another cluster" anyway.
- All 15 matched spellings use precomposed letters (é, è, î, à). The port reproduces exactly the 15 and excludes
  11221362 and 22751177 (the Greek omissions).

**D573-4. New epoch `524u2-v14`, salt 2,780,004,659 (the low 32 bits of FNV-1a 64).**
- The decision says "a new head-election epoch". The wet path refuses a plan from another epoch, and each epoch
  draws its samples anew.
- The salt moves the pinned sample keys and one integration draw (section 3.4).

**D573-5. `R0d` joins `ORG_NAME_REFRESH_EXCLUDABLE_RULES`. The runbook's filters stay
`["R2","R0w"]` + `["unfit"]`.**
- This is decision point 5. The const becomes `["R0d", "R0e", "R0n", "R0w", "R1", "R2"]` (sorted; "names every
  rule" now needs all six).

**D573-6. No canary is added.**
- The exhibit would read `keep:S1` after the wet run, so it would need a re-point at the next build (the v12
  precedent).
- The GO read lists the R0d ids from `planned` directly (section 6.3).

**D573-7. The apply is a full-walk dry plan, then a wet run scoped by `org_ids` to the R0d ids. No full wet run.**
- The full walk is cheap: plan 2653's `computed_at − as_of` is 184 s for 5,680,353 orgs. It is also the only way to
  catch an R0d outside the 15: a matching spelling ranked below an entry's top 5, which size.md lists as a
  lower-bound caveat.
- The `org_ids` wet run ships exactly the decided set. The decision requires any other R0d item to be read before a
  wet run, so extras join `org_ids` only after a read.
- R1 changes elected since job 2654 are routine upkeep under the runbook. They are not this unit's.

**D573-8. No project and no refold.**
- A rename is a read-time join. It writes `organization changed` rows and no Tender row (CHANGELOG, issue 524 unit
  2b section).
- 548's job 2654 ran with none, and its 8/8 persistence read-back passed after the next daily fold.
- The fast plan (`551-lot-sum/b6/fast-plan.md` §1, "Allowed earlier, between 577 slices") already admits "573's dry
  re-plan and wet 15" as their own short segment. Where 551's gd5 registry is live, it is class Z: 0 tender rows
  expected.

**D573-9. The served docs change.**
- The served rule says a change "on the 55% arm" waits while the head was printed within 3 years. For an R0d head
  that is no longer true, so all three surfaces gain one sentence (section 4). A docs test pins it.
- The CHANGELOG gains a Rule v14 paragraph, as v10–v13 did.

**D573-10. Deploy class: not a fold change.** It touches the refresh-org-names planner and wet pre-pass only.
- It rides the next deploy ("deploy #3 if it is confined to the planner": fast-plan.md line 280; it is).
- No P-probe prediction changes.
- The dry plan and the wet run must run on the deployed binary: a plan from another `rev` is refused.

**D573-11. Accepted cosmetic flaw (size.md).** The two Pointe-à-Pitre orgs will serve

```rust
/// Issue 573 (rule `v14`): whether `head` is `spelling` with its accented letters DROPPED — what a decoder
/// that deletes the bytes it cannot read leaves (22435268 `Comit consultatif interrgional du rglement amiable`
/// for `Comité consultatif interrégional du règlement amiable`). All three hold:
/// - `spelling` with every non-ASCII character deleted (letters, marks, a no-break space, typographic
///   punctuation) equals `head`, both whitespace-collapsed ([`collapse_whitespace`]) and compared ASCII
///   case-insensitively — so a head with any non-ASCII character never matches;
/// - some word of `spelling` (split on whitespace) lost a letter and kept an ASCII one: a partial drop
///   (22399787 `Pointe--Pitre` from `Pointe-à\u{a0}-Pitre`: the `à` and its no-break space went);
/// - no word of `spelling` is 2 or more non-ASCII letters with no ASCII letter: that is an omitted word, not a
///   dropped accent (11221362 `Johnson & Johnson Hellas` against `… HELLAS ΑΕΒΕ`).
///
/// A letter is [`char::is_alphabetic`]. A decomposed accent (a combining mark) is not one: a head that lost
/// only marks is the diacritic-folded spelling, which the vote key already joins to it.
pub fn head_dropped_accent(head: &str, spelling: &str) -> bool {
    let stripped: String = spelling.chars().filter(char::is_ascii).collect();
    if !collapse_whitespace(&stripped).eq_ignore_ascii_case(&collapse_whitespace(head)) {
        return false;
    }
    let mut partial = false;
    for word in spelling.split_whitespace() {
        let lost = word.chars().filter(|c| !c.is_ascii() && c.is_alphabetic()).count();
        let kept = word.chars().any(|c| c.is_ascii_alphabetic());
        if lost >= 2 && !kept {
            return false;
        }
        partial |= lost >= 1 && kept;
    }
    partial
}
```

`collapse_whitespace` (line 1128) is a private fn in the same module, so it can be used here. `split_whitespace`
splits on U+00A0, which reproduces Python's `str.split()` on the Pointe-à-Pitre spelling.
