## 1. Decisions made here

- **D561-1. Unit 3 folds into unit 4's commit.** Its CHANGELOG wording (551's two lot-sum legs, the adversarial's
  corrected phrasing) goes into the narrowed 547 bullet in its final form (§5.1). Its Verify replacement is step 0.
- **D561-2. The "Blocked by: 551 closing" hold is void** (owner ruling 2026-10-24: a watch never blocks work). What
  still binds: one writer on the box (deploy only with the queue idle: after 546 U4's jobs 2764/2765, and never under
  a running project), a green gate on the deployed tree, and the 551 switch-off twin re-gated on the new base after
  the deploy (551's C7; it informs, it does not block). Why it does not confound 551's U9 watch: the quiet refresh
  is counted as `values_refreshed`, never `corrected`; U9 reads served `lot-sum-awards` heads by marker, which no
  part of this unit moves (the head election is unchanged).
- **D561-3. The quiet column is one named const, not a new `LeafTable` field.** `QUIET_VERSION_COLUMN =
  "value_eur_cents"` on `Leaf::Versions` only; the equality skips that position for that table. Same behaviour as the
  decision's "LeafTable gains a quiet column", without editing 14 descriptor literals.
- **D561-4. The head UPDATE keeps its own election** (the decision's "reuse the last version's HeadValue" is not
  done). After the loop the rule is in the same state (`set_head` overwrites), so the result is identical by
  construction; reuse would need the shrink-path special case the check flagged; and 551's one-writer pin
  (`head_election_agreement.rs:1340`, the literal `let value = head_value_eur_cents_with(head, &partners, &rates);`)
  stays green. Cost: the one election per written Tender that runs today.
- **D561-5. New finding — the shrink path must restate the kept head's stored value.** A non-stale chain cut back to
  its kept prefix (`keep == p.versions.len() < stored.len()`) runs no write loop; the head UPDATE re-elects at today's
  rates, while the kept head version's stored value was elected at its own fold's rates. With a non-EUR Tender whose
  rate moved since, the new head gate (D561-8) would fail the batch and wedge the project job. Fix: in that case run
  the quiet UPDATE for seq `keep` with the head's value (4 lines, §3.1 i). Pinned by
  `a_shrunk_chain_restates_its_kept_heads_value_at_todays_rates`.
- **D561-6. Migration through `add_column`, not `MIGRATIONS`,** because the boot that first adds the column must
  record the reset horizon. The horizon is the change log's AUTOINCREMENT high-water from `sqlite_sequence` (O(1), as
  `lib.rs:4929 max_cursor` reads it), never `MAX(cursor)` (a full scan of ~80 M rows on prod, issue 61).
- **D561-7. The adversarial's preferred reset is adopted** (it was BLOCKING): `projection_state.value_probe_cursor`;
  `v1::sse::start` answers a resume of a `/v1/tenders` or `/v1/lots` stream with `min_value` or `max_value` whose
  cursor is below it with `reset` `{"reason":"value_probe_changed"}`. Polls and webhooks are unfiltered and probe no
  value: untouched. A fresh DB records 0 (the column is in its CREATE), so tests set it by hand.
- **D561-8. The head gate (`assert_heads_match`) gains the value check as a hard error**, as the decision says, and a
  Tender whose only write was a quiet refresh is returned for it (the check's amendment). D561-5 makes it sound.
- **D561-9. Roll-forward after a rollback is not automated.** The old binary cannot signal, an env-var knob would be
  untested code, and the event is rare. operations.md says: after a roll-forward, put the residual on the operator
  notice (banner). The residual is stated in ADR-0017's amendment.
- **D561-10. 551's derivation marker does not go per version in this bump** (the check's scope question for 566).
  Smallest change that fully does 561. 566's issue gets the note that a derived superseded version serves
  `value: null`, and that a per-version marker needs its own epoch (6) plus quiet columns, which this unit's quiet
  rule makes a verify-and-UPDATE, not a replay.
- **D561-11. The column keeps the name `value_eur_cents`** (the Verify greps it) and gets an exact
  `("tender_versions", "value_eur_cents")` column note, so the wildcard lot note (`sql.rs:1265`, "award results are
  never elected") cannot apply.
- **D561-12. The api reproductions use 560's R2.0.9 helpers** (`r209_cn`, `r209_f14`, `total_change`), which carry a
  procedure total and one lot figure exactly as the issue's reproduction needs. R2.0.9 has no BT-709, so the
  partner-only case is pinned in the store-level per-prefix test (551 fixture 1024214 carries a BT-709 framework
  maximum) and the api min_value case uses the refused-figure variant (lot at EUR 200 bn), which the issue
  reproduced to the same effect.
- **D561-13. The golden wall-time measurement is replaced** by the canary's compare line (`us per version`, the
  prod cost of the extra election on compared prefixes). Informational either way; no bound.
- **D561-14. The runtime timing pin runs in the gate** (not `#[ignore]`), with ratio bounds and margin (measured 25×,
  asserted 5×), so it cannot be skipped and should not flake.
