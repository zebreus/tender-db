## 1. Decisions (made here, with reasons)

**D1. M6 is adjudication plus existing arms. No build is needed before the box run.**
- `POST /admin/identifier-verdicts` takes any identifier up to 64 characters (admin.rs:454-520). The store keys
  each verdict by the triple the org carries (canonical.rs:34351-34465).
- The `rekey` arm (canonical.rs:34475-) keys the reviewer's right number through
  `crosswalk::canonical_key_flat` (supervisor.rs:13939-13950):
  - a GB-PPON correction keys `GB:ppon` E1 (crosswalk.rs:391-397);
  - a company number keys `GB:coh` E1 (crosswalk.rs:398-427);
  - a GB-NHS value or code keys nothing (it falls to `_ => None`, crosswalk.rs:429-433), so it is `unkeyed`
    (canonical.rs:34553-34556).
- So the decision's §4 table runs today exactly as written (`unit2-decision.md` §4: "The rekey merges it
  **today**").
- The test in §5 only pins this. It changes no runtime behaviour, so no deploy is owed.

**D2. An NHS body's own row under a non-code or typo GB-NHS value takes the body's standing PPON org as
`correct_identifier`. This is QHL15E's route, applied to the rest of the cohort.**
- QHL15E is a class-E row: ODS 404, and two codes glued. Decision §4 already routes it to the PPON of QHL's
  survivor 30916123 (`GBPPONPWQY9673JBYN`, closing plan 2348).
- The same shape covers 38 more rows in the prior (`body-ppon`, 96 mentions). Examples:
  - `110001` Gloucestershire Hospitals → 30913986;
  - the five `OCDS…` rows of Countess of Chester, Calderdale and Huddersfield, North Cumbria and LLR ICB;
  - `RF1` → the Isle of Wight PPON row 31571667;
  - `T6YOW` → the Norfolk and Suffolk ICB PPON row 31580764;
  - `QE1000` → QE1's PPON row 31569664 (M5).
- Why this is right:
  - It needs no code.
  - Every merge is reviewed: reader and challenger must agree HIGH, and the arm applies its own name gate
    (canonical.rs:34747-34760).
  - The target is the body's canonical PPON row. That is the survivor tier 513, 519 phase A and U6 all choose,
    so no later unit has to undo it.
  - It removes body splits ahead of 469 U7.
- **Ruling 8 stands.** No `GB:nhs` key is built. A typo whose body has **no** standing PPON org still gets the
  right ODS code as its correction (`unkeyed`), so it is withheld and flagged only.
- **Exclusions. These never take a PPON correction:**
  - NHS England offices, regions and hubs. Issue 523 owns NHS England. A `wrong` verdict does not stop 523 from
    later re-POSTing with a correction.
  - Sites, places, hosted units, pathology networks and collaboratives. This is 513's `HOSTED_OR_SITE`

  - Any row whose mention names include another body's. These go at medium and are listed; a 317 rehome is out
    of scope here.
  - Provisional anchors. The arm cannot target them anyway: owners must carry the right number.

**D3. A PPON correction with no standing owner, and every split review, goes at `medium`.**
- With no standing owner the arm plans a **move**. The move writes `right`, the bare canonical serial
  (canonical.rs:34690-34694), and a bare serial keys nothing (crosswalk.rs:392 needs the prefix). The next
  PPON-first mention would then mint a new org. Ruling 8 holds PPON moves.
- `medium` still withholds and flags the row: `withheld_identifier_triples` reads `verdict = 'wrong'` with no
  confidence filter (canonical.rs:12241-12255). It also never re-keys: the arm counts it `not_high`
  (canonical.rs:34528-34531).
- The prior expects at most 4 such rows: `PBND1678TCRM`, `PHPY3425XCGD`, `PNNX5248NRVD` and `PWNJ1991NGDW`.
  R4 (§4.1) settles each one.

**D4. A company number is corrected only after a register check.**
- The correction is the 8-character number, zero-padded. A 6-7 digit body is E2 (crosswalk.rs:428), which the
  arm refuses as a right number (canonical.rs:34553-34556).
- The check is 452's right-number test: the register's current or a previous name is the org's. Use
  `453-rekey/ch_check.py`'s fetch and score.
- If the register names someone else, or answers 404, the row is `wrong` with no correction, unless the review

- A company move writes the bare 8-digit number, which keys `GB:coh` E1. Decision §4 accepts this.

## 3. The cohort and the review rubric

### 3.1 Scope

Start from the live re-read in §4.1. Every org of `country = 'GB'`, `identifier_kind = 'national'` and
`identifier` from `GBNHS` up to `GBNHT` belongs to the cohort when its code (the literal after `GBNHS`) meets
one of these:
- it was class E or F in `519-nhs-digit-codes/gbnhs-orgs-classified.json` (`ods.found` is `false` or `null`);
- it is new since 2026-10-12 and is either not ODS-shaped (`fetch_ods.py`'s regex
  `[A-Z0-9]{3}|[A-Z0-9]{5}|[A-Z0-9]{6}` fails) or answers 404 on an ODS fetch (`fetch_ods.py`, cached under
  `ods/`).

These stay out:
- sub-ICB and site children (phase A or held);
- class C (NHS England under real codes → 523);
- classes D, G and H (correct own codes);
- the miscoded real codes (RJ7, Y54, Y61, Y62, RH8C3, D8D1G; decision §4, last row).

### 3.3 Rubric: `519-nhs-digit-codes/m6/rubric.md` (the implementer writes this text verbatim)

> Each case is one organization whose identity is a GB-NHS value that is not an NHS ODS code. You see its id,
> literal, head name, every mention name with counts and raw identifiers, the shape of the value, and candidate
> right identifiers with evidence: a same-name PPON or company-number row (id, literal, name), the 513/519
> survivor of the code the value seems to spell (`code_survivors`), and register answers for company numbers.
> Give ONE row: `verdict` (`wrong` | `right` | `skip`), `correct_identifier` (or null), `expected`
> (`{shape: merge|move|unkeyed|none|hold, target: <org id or null>}`), `confidence` (high|medium|low) and a
> two-sentence `rationale` naming the evidence.
>
> - A **PPON value**: when a standing org carries `GBPPON<value>` and IS this organization (by its names):
>   `wrong`, `GBPPON<value>`, `merge` into it. When it is a different entity (a host trust): `wrong`, no
>   correction. With no standing owner: `wrong`, `GBPPON<value>`, `hold`.
> - An **NHS body's own row** (a trust, ICB, health board, ambulance service, NI HSC body) under any other
>   value: when a standing PPON org is that body (the same-name PPON row, or the survivor of the code the value
>   spells): `wrong`, its `GBPPON…` literal, `merge` into it. Only when EVERY mention name is that body's.
>   Never for NHS England, a site, place, hosted unit, network or collaborative.
> - A **company number**: when the register's current or a previous name is this organization's: `wrong`, the
>   8-character number, `merge` (a standing org carries it) or `move` (none does). Otherwise `wrong` with no
>   correction, unless you find its own number or PPON on a standing same-name row.
> - A **mistyped or glued NHS code** whose body has no standing PPON org: `wrong`, the right ODS code,
>   `unkeyed`.
> - **NHS England** (regions, offices, hubs, health and justice): `wrong`; the NHS England code if the value
>   spells one (`unkeyed`), else none. Never a PPON.
> - **Anything else**: `wrong`, no correction, `none`.
> - `right` only if the value IS this org's valid identifier under GB-NHS (not expected). `skip` if the org is
>   gone or you cannot settle it; say what would settle it.
> - `high` only when the evidence is plain. Mixed mention names (another body's or a supplier's) are never
>   `high` for a merge.

- Merge the two into `m6/verdicts.json`, one row per org:
  `{org, identifier, route, verdict, correct_identifier, expected{shape,target}, confidence, rationale,

    never re-keys.

- QHL15E's row is fixed: `wrong`, `GBPPONPWQY9673JBYN`, `{merge, 30916123}`, high. Decision §4 and the U3 panel

### 4.4 `post_body.py`: verdicts → the POST body (modelled on `452-census/verdict_post.py`)

```python
#!/usr/bin/env python3
"""519 M6: verdicts.json + live.json -> POST /admin/identifier-verdicts body.
usage: post_body.py m6/verdicts.json m6/live.json <cohort> m6/post-body.json"""
import json, re, sys, collections
verdicts_p, live_p, cohort, out = sys.argv[1:5]
live = {r[0]: r[1] for r in json.load(open(live_p))['orgs']}          # id -> identifier, as R1 read it
body, why = [], collections.Counter()
for v in json.load(open(verdicts_p)):
    if v['verdict'] not in ('wrong', 'right'):
        why['not posted: ' + v['verdict']] += 1; continue
    lit = live.get(v['org'])
    if lit != v['identifier']:
        why['gone or re-keyed since R1'] += 1; continue
    if len(lit) > 64:                                                   # admin.rs:474-479 (D8)
        why['identifier over the 64-char POST cap'] += 1; continue
    c = v.get('correct_identifier')
    if c:
        n = re.sub(r'[^A-Z0-9]', '', c.upper())
        if 'PPON' in n[:6]:
            c = 'GBPPON' + n.split('PPON', 1)[1]                        # crosswalk.rs:392 needs the prefix
        elif re.fullmatch(r'(GBCOH)?\d{6,8}', n):
            c = n.removeprefix('GBCOH').zfill(8)                        # E1 only (D4)
        else:
            c = n.removeprefix('GBCOH').removeprefix('GBNHS')           # 2+6 register form, or an ODS code
    conf = v['confidence'] if v.get('challenger_agrees') else 'medium'
    if (v.get('expected') or {}).get('shape') == 'hold':
        conf = 'medium'                                                 # D3
    body.append({'org_id': v['org'], 'identifier': lit, 'verdict': v['verdict'],
                 'correct_identifier': c,
                 'rationale': f"[519 M6 {v['route']}/{v['confidence']}] {v['rationale']} | challenger: {v.get('challenge') or ''}"[:4000],
                 'confidence': conf})
    why[f"{v['verdict']}/{conf}/{'corrected' if c else 'bare'}"] += 1
print(dict(why), '| posted', len(body))
json.dump({'cohort': cohort, 'verdicts': body}, open(out, 'w'), indent=1)
```

### 4.5 `plan_diff.py`: the dry plan held to the review before the wet run

```python
#!/usr/bin/env python3
"""519 M6: hold the dry rekey plan to the reviewed expectation.
usage: plan_diff.py m6/rekey-plan-dry.json m6/verdicts.json m6/post-body.json m6/holds.json <hold cohort>
exit 0 = run the wet; 2 = holds written (POST them, re-run the dry, re-run this); 3 = STOP, read first."""
import json, sys
rep, ver_p, body_p, out, hold_cohort = sys.argv[1:6]
r = json.load(open(rep)); plan = json.loads(r['body']) if isinstance(r.get('body'), str) else r
posted = {v['identifier']: v for v in json.load(open(body_p))['verdicts']}
exp = {v['identifier']: (v.get('expected') or {}) for v in json.load(open(ver_p))}
stops, holds, planned = [], [], set()
for l in plan['plan']:
    w = l['wrong']; planned.add(w); v = posted.get(w); e = exp.get(w, {})
    if v is None:
        stops.append(f"{l['key']}: not an M6 verdict (an older cohort's key drifted into the plan): read it"); continue
    if l['shape'] == 'move' and (v['correct_identifier'] or '').startswith('GBPPON'):
        holds.append(dict(v, confidence='medium', rationale=(v['rationale'][:3700] +
            ' | 519 M6 hold: no standing owner; a PPON move writes the bare serial (ruling 8)')))
        continue
    if l['shape'] != e.get('shape'):
        stops.append(f"{l['key']}: planned {l['shape']}, reviewed {e.get('shape')}"); continue
    got = (l.get('target') or {}).get('org')
    if l['shape'] == 'merge' and e.get('target') is not None and got != e['target']:
        stops.append(f"{l['key']}: target {got}, reviewed {e['target']}")
for l in plan['denied']:
    if l['wrong'] in posted:
        print(f"NOTE {l['wrong']}: denied {l['shape']} (residue; pending-move merges on the second pass)")
for w, v in posted.items():
    if v['confidence'] == 'high' and exp.get(w, {}).get('shape') in ('merge', 'move') and w not in planned \
            and not any(l['wrong'] == w for l in plan['denied']):
        print(f"NOTE {w}: reviewed {exp[w]['shape']}, neither planned nor denied (gone / several / unkeyed)")
print(f"plan {len(plan['plan'])} keys; holds {len(holds)}; stops {len(stops)}")
for s in stops: print('STOP', s)
if holds:
    json.dump({'cohort': hold_cohort, 'verdicts': holds}, open(out, 'w'), indent=1)
sys.exit(3 if stops else 2 if holds else 0)
```
