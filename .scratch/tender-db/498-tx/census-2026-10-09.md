## Helper design (verifier)

PLACEMENT AND SIGNATURE. Add a new module crates/store/src/tx.rs (`mod tx;` in lib.rs). Move finish_tx out of canonical.rs:1647 into it, and add an associated function on Db. That makes it 'Db-level' and keeps call sites in the existing `Self::assert_heads_match(&conn, ..)` style:

```rust
impl Db {
    /// BEGIN IMMEDIATE, run `body`, COMMIT. On ANY error from the body or the COMMIT: best-effort ROLLBACK and return the ORIGINAL error (issue 498).
    /// `body` must be a lazy future (an `async {}` block or an `async fn` call); it is first polled AFTER the BEGIN succeeds.
    pub(crate) async fn immediate<T>(conn: &Connection, body: impl Future<Output = turso::Result<T>>) -> turso::Result<T> {
        Self::within(conn, "BEGIN IMMEDIATE", body).await
    }
    /// The same with an explicit BEGIN form, so the two plain-`BEGIN` sites (canonical.rs:11352, lib.rs:4018) convert byte-identically.
    pub(crate) async fn within<T>(conn: &Connection, begin: &'static str, body: impl Future<Output = turso::Result<T>>) -> turso::Result<T> {
        conn.execute(begin, ()).await?; // nothing opened: no ROLLBACK, and never end a transaction this call did not open
        finish(conn, body.await).await
    }
}
pub(crate) async fn finish<T>(conn: &Connection, result: turso::Result<T>) -> turso::Result<T> {
    let err = match result {
        Ok(v) => match conn.execute("COMMIT", ()).await { Ok(_) => return Ok(v), Err(e) => e },
        Err(e) => e,
    };
    rollback_best_effort(conn).await;
    Err(err)
}
async fn rollback_best_effort(conn: &Connection) {
    // turso has sometimes already ended the transaction itself: RAISE(ROLLBACK), a poisoned transaction at COMMIT, a generic error on a single-row write or a read, or an I/O failure after op_auto_commit flipped auto_commit.
    if conn.is_autocommit().unwrap_or(false) { return; }
    let _ = conn.execute("ROLLBACK", ()).await; // its error never replaces the original
    if !conn.is_autocommit().unwrap_or(true) { eprintln!("[store] ROLLBACK left the shared writer inside its transaction (issue 498)"); }
}
```

Why take a future rather than a closure? It is exactly how sites are already written: `let result = async {..}.await; finish_tx(&conn, result)`. Futures are lazy, so BEGIN still runs first. The body can borrow `&conn`, `&mut stmts`, `&mut pending`, `resolver: &mut _` and `&mut report` without higher-ranked lifetime trouble, and those borrows end when immediate returns. The alternative is `F: AsyncFnOnce() -> turso::Result<T>`, which edition 2024 allows; it removes the 'lazy future' caveat at the cost of a novel idiom in this codebase. Box::pin the big bodies at the call site (apply_tenders, twin_repair, repair_placeholder). The helper is generic and holds the body inline, so a large body enlarges the caller's future, and CLAUDE.md records that this has already overflowed the stack once.

FIT WITH THE GUARD STYLE. The caller keeps `let conn = self.conn().await;` (the MutexGuard) and passes `&conn`; the guard derefs to &Connection. Nothing in the helper touches the mutex. Checkpoints, publish_cursor and counters stay outside the call, after Ok, exactly where they sit today.

OPTIONAL DEFENSE IN DEPTH (recommended, separate unit). This is the only fix for the panic and cancellation cases above. In Db::conn_for (lib.rs:1191), after taking the guard: `if !guard.is_autocommit().unwrap_or(true) { eprintln!(\"[store] writer handed over INSIDE a transaction (waiter {caller}); rolling it back (issue 498)\"); let _ = guard.execute(\"ROLLBACK\", ()).await; }`. It mirrors the reader pool's is_autocommit check at read.rs:150. Precondition: no code spans one transaction across two conn() acquisitions. Every BEGIN..COMMIT in the 61 sites sits inside one guard, and nested acquisition would deadlock on the tokio mutex anyway.
