How strong the splits are (one-sided Fisher tests):
- Stale against fresh: 4/39 against 1/81, p = 0.038. This was itself found after looking.
- Inside stale, B's `second > head` split: 3/10 against 1/29, p = 0.045. It was picked from at least three families tried.
- Inside stale, any rival: 3/17 against 1/22, p = 0.21.

**No qualifier is statistically identified on these labels.** The choice rests on mechanism, below.

**Mechanism.** Take a shipped R1 change whose top is stale and which has no rival. v8's residue holdout and v10's `head_current` already guarantee two things:
- the head's newest print is at least 3 years old;
- the org's newest item is not a head item.

With only two clusters voting, the elected spelling is therefore the org's newest printed name. Neither failure that sank job 2555 can occur in this cell:
- a supersede, where a newer third name exists (1276213);
- a revert, where the head's name is printed again in another spelling (1556789).

Both failures need a rival. So `rival` is the necessary condition for the failure mode, and a vote count is not.

B's `second > head` filters rivals by votes. But a superseding name is young, so it has had fewer notices than a head printed for years. The bias shows in the labels:
- 8507094: the newest name is Ayvens, printed since 2024-11. It has 5 votes against the head's 13, so it sits in the cell B ships. It reads neutral only because the head is equally out of date.
- 1556789: B catches it only because its revert spelling has 9 votes against H = 1. With 1 vote, B ships a revert, and reverts have a bar of 0.

My by-name read of 22 random entries from the cell B ships and v11 holds:
- about 15 look right and about 3 neutral;
- about 4 look like another entity or a weld: 15219886 (an SPW roads directorate → SOFICO), 11121683 (RSK Group → RSK Ireland, with a Bulgarian RSK cluster), 11994669 (a West Suffolk NHS FT cluster), 15698990.

The stale no-rival cell is safe from supersede and revert by construction, but not from other shapes. A by-name read of 24 found 3 risks:
- 16394646: Szczecińskie Inwestycje Miejskie → Gmina Miasto Szczecin, another entity;
- 3923522: an association → its member;
- 13227931: `CCAS d'Épernay` → a generic name.

It therefore ships only behind gate (a) in the protocol, with A's rule ready as the fallback.

### The rule (`524u2-v11`, on v10)

Every piece is pure over values `elect_head_counted` already holds, and each is in the stored plan entry: `top_newest`, `clusters`, `head` (H), the two names, `identifier`, and the plan's `as_of`. **No DB read and no new verdict input.** `head_vote_key` and `NAME_KEY_EPOCH` are unchanged.

1. **`top_stale`** (`HEAD_HOLD_TOP_STALE`, `HEAD_TOP_STALE_DAYS = 365`)
   - **When it holds:** an R1 verdict that is still a Change after serve and after `head_current` is HELD `top_stale`, with the spelling it would serve, when both conditions are true:
     - **rival:** `clusters > 1 + (head_votes > 0)`;
     - **stale:** the reading's `top_newest` is before `as_of − 365 × 86,400`.
   - **Fail closed:** no reading, or no `top_newest`, counts as stale. This happens 0 times on plan 2543.
   - **Exempt:** a head that the window, the residue holdout or `head_current` already released (`read.released` is Some) ships. 3042 keeps `change:R1`.
   - **The junk exemption:** `top_stale` does **not** ask it, so no new release is minted. About 100 stale-rival heads with a digits token stay held.
   - **Rules:** R0 and R2 are exempt.
2. **Serve hold `doubled`**, in `head_serve_hold` after `caps_variant`, for R1 and R2.
   - It fires when T(display) is X·X: X non-empty, with a token of 3 or more chars.
   - It does not fire when T(head) has that form too.
   - The separator split in B's text is redundant: separators are not alphanumeric, so X·X already covers it.
3. **Serve hold `seat_dropped`**, after `doubled`, as B specified:
   - T(head) = T(display) + tail, with |T(display)| ≥ 2;
   - the tail is 2–3 tokens with no digit;
   - tail[0] is one of {w, we, v, ve, vo};
   - that preposition is followed by whitespace in the head text, so `v/…` agent tails still change.
4. **Bind guard `placeholder_id`**, in `head_change_hold`, for every rule.
   - It fires when the identifier matches `(?i)^(keineangabe|unbekannt|nichtvorhanden)\d*$`, or is all ASCII zeros.
   - B's `telefon` is dropped, and UNBEKANNT2 and NICHTVORHANDEN1 (the same family) are added.
5. **Order, first match wins:** E1–E3 → R0 → D4 → S1 → bars → window → residue → serve (bind guards with placeholder_id → r2_hold → the seven serve holds) → head_current → top_stale.
   - `HEAD_SERVE_HOLDS` grows to 7.
   - Every v9/v10 hold keeps its reason. The new serve holds do take some entries from `head_current`, as counted below.
6. **Pre-built wet filter `exclude_stale_top`** (A's rule, the fallback).
   - Before the pre-pass, it drops every non-release R1 target whose stored `top_newest` is missing or older than the plan's `as_of − 365 d`.
   - At wet time, a target whose re-elected reading reads the same drifts, as for `exclude_released`.
   - It is off unless gate (a) fails.
7. **Diagnostic only:** plan entries gain `rival_newest`, the newest dated item of any cluster other than the elected one and the head's. It comes from the same dated rows, and no verdict reads it. It is there so 548 can measure the direct supersede test.

The wet pre-pass re-elects with the stored `as_of`. A new third cluster or a new print after the plan can only turn a planned change into drift.

   - `seat_dropped`: holds 5350675; does not hold `Sandefjord kommune v/VOIS` → `Sandefjord kommune`; does not hold 2643237 (a seat added).

   - `rival_newest` is emitted and read by no verdict.
   - `head_vote_key` and `NAME_KEY_EPOCH` are unchanged.
2. **Deploy in a queue gap and re-plan** (full walk). Go when all of these hold:
   - undated 0;
   - 0 unexpected canaries;
   - each count within ±10 % (floor ±10) of the expected numbers: top_stale about 2,430, doubled about 91, seat_dropped about 67, placeholder_id about 10, head_current about 6,302, R1 changes about 15,936. A larger gap is a port bug to reconcile first.
3. **Dated re-judge.** Samples are salted by the epoch, every labelled and panel-read org is skipped, and a skeptic reads every wrong.
   - **(a) stale no-rival, 30** (v11 R1 changes with top age ≥ 365 and no rival): ≤ 1 wrong, 0 reverts. A fail is not a stop: every wet run then also passes `exclude_stale_top: true`.
   - **(b) change:R1, uniform 30:** ≤ 1 wrong. A fail stops the run for a re-decision.
   - **(c) change:R1, low-id 30** (from the lowest 2,000 in-scope targets by org id): ≤ 1 wrong, 0 reverts. A fail stops the run.
   - For (b) and (c), only items the wet runs will apply count. If (a) fails, stale items are skipped and the draw continues in salted order to 30.
   - **(d) Cost report of 30, not a gate:** top_stale 20, seat_dropped 5, doubled 5 (half ≠ head). A reason that reads more right than wrong goes to 548.
4. **Wet canaries:** 8765882, 5393731, 9856301, 7822785, 11268197 and 5011106 (fresh top, judged right), plus 2857103 and 2715115 only if (a) passed. Expect every one RENAMED and 0 drifted.
5. **Capped 500** (lowest ids). Dated spot check of its 30 `applied_samples`, reading the head's and the elected spelling's dates: 0 former-name reverts, ≤ 1 other wrong. A fail reverts the job at once and stops.
6. **Full run.** Its `applied_samples` get the same dated check; a fail reverts the job.

Every wet run passes `exclude_rules: ["R2"], exclude_released: ["unfit"]`, plus `exclude_stale_top: true` if (a) failed.
