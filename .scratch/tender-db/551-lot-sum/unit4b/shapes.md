# Issue 551 path W: mechanical shapes of the 105 wrong and 14 neutral heads (input to unit 4b)

## Inputs and method

- **Labels.** `.scratch/tender-db/551-lot-sum/postdrain/read_result.json`: 279 heads, 160 right, 14 neutral, 105 wrong. I read every wrong's and neutral's "why", plus the skeptic check where one exists (107 of the 119).
- **Lot data.** `/v1/tenders/{id}` for all 279 heads. 174 came from the post-drain read's own cache (`scratchpad/v551`). The other 105 I fetched today, one GET every 2.5 s or more, with no 408s.
- **The sum reproduces exactly.** I rebuilt path W's summed set from the API's `lot_results`: each counted Lot's latest award by notice id, figure above 10.00, not a sentinel. The result equals the served `lot-sum-awards` value **to the cent on all 279**, and every head still served its derived value when read. So every feature below is computed on exactly the summed set.
- **Files.**
  - `scratchpad/d551w/shapes_work/features.py` (the features), `features.json` (per id), `evalf.py` (hit counts), `assign.json` (shape per id).
- **How to read the counts.** "W/N/R" counts how many wrong, neutral and right heads a feature fires on, out of 105 / 14 / 160. **Every threshold was chosen on these same 279 labels**, so the counts are in-sample and optimistic. A fresh uniform sample and a fresh band read must re-measure them.
- **Facts that are NOT exposed today:**
  - BT-765 (the framework flag): only `dps` reaches classifications.
  - BT-710/BT-711 (lowest/highest tender).
  - BT-118/BT-1118 (unmapped, issue 506).
  - TED `TED-LOT_NO`: stored per the code, but not in the API.
  - Provenance of a lot-null amount (procedure-section II.1.7/BT-161 vs a lot result's own value copied to tender scope).
  - TED lot estimates: these are stored lot-null, so no TED lot has a keyed estimate.

## Notes

- **The labels disagree on the Swiss multi-winner shape** (per-lot CAN, BT-161 = Σ of 2–20 winners' offers):
  - right: 774597, 813070, 1150222, 281136, 185592, 820038, 1074798;
  - neutral: 84717, 533202, 568959, 1013115;
  - wrong: 435520, 448070, 540682, 776640, 762774, 70706, 176280, 433504, 524007, 973781, 1059375, 1140313.

  No API field separates them. Any guard on that shape trades about 10 rights for about 20 wrongs. Under the house rule (fail closed; a refused sum falls back to one lot's figure), refusing all of them is the conservative call.
- **Path W's existing guards miss these shapes:**
  - G1' only sees repeats at ≥ 1/10 of the largest lot (27915, 831972 and 7056700 repeat small figures).
  - G3 compares the largest lot with the others only; it never includes the lot's own superseded award (5316736's GBP 680 m = 20 m + 660 m).
  - G4 needs a ratio above 10× over ≥2 lots (6956639 is exactly 10×; 136136 is 9.8×).
  - G8b reads key spelling only (LOT-0000/0001, LOT-0001/0002 re-keys pass).
