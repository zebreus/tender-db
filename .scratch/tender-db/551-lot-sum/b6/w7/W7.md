## 2. Method

**Set A: every id 577 U2 can move, plus every id in 577's lists.** `set_A.tsv` holds 631 ids, each tagged
with where it came from.

- **Moves the code can cause.** These come from `emulate_577u2.py`, which writes `moves_bind.tsv` and
  `moves_extra.tsv`. It is a port of `index::build` at HEAD plus `Index::bind` (D577-1), done two ways.
  - *Bind moves.* The script ports the commit's own index-wide test,
    `a_declared_field_binds_over_a_patch_only_where_d577_1_says` (it copies `co_bound`, `co_match`,
    `select_order` and `bind`).
  - *EXTRA moves.* The index is built twice, once with the top-level EXTRA insert `gap_only=false`
    (before the commit) and once with `true` (after). Every branch whose bound id differs is listed.
  - *Validation.* The port reproduces every pin of the two gated tests exactly (`emulation_check.txt`:
    "ALL PINS MATCH: True"; 577 records the gate green at 406529a). The pins are:
    - every SDK-shaped inventory's moved set, for example 1.3–1.7 = {BT-23-Lot→BT-23-Procedure,
      BT-531-Lot→BT-531-Part, BT-772-Lot→BT-67(b)-Procedure};
    - eforms-de-1.x at 118 pairs and 113 declared ids, the 3 non-lot declared ids, and the 4 named pairs;
    - sdk-0.1 with no moves;
    - the EXTRA diff equal to exactly the 4 pinned overwrites.

  The test pins de-1.x only by count; the port names all 118 pairs. Together that is 125 distinct
  (old, new) pairs and 237 ids.
- **577's lists.**
  - `577-triage/shadow.out`: 155 shadow rows, and the overlap section's 4,811 pairs (1,303 distinct).
    The script asserts the 4,811.
  - `577-triage/shadow_extra.out`: 24 rows.
  - `577rec/` does not exist; 577:65-67 says it stayed in a session scratchpad.

**Set B: every field id or stem the fold reads.** `set_B.tsv` has 428 entries, each labelled by tier.

- *Source.* `scan_fold_literals.py` (output `fold_literals.tsv`) lists every field-id literal in the
  fold's production code at HEAD:
  - `project.rs` minus its `#[cfg(test)]` items;
  - the production halves of `guid_twin.rs`, `key_census.rs`, `role_census.rs`, `escapes.rs` and
    `title_key_nfkd.rs`. `lot_keys_570` and `lot_guards_568` are test-only.

  `build_sets.py` classifies each literal by the const or fn that holds it. It also adds the reads that
  are not literals:
  - the `VALUE_COST` suffix;
  - `OCDS-ContractValue`;
  - the `OPT-300-`/`OPT-301-` role prefixes;
  - every `DE1_FIELD_ALIASES` source. Each DE1 source takes the categories of the eForms target that
    `normalise_de1` (project.rs:11313) rewrites it to before any read.
- *Tiers.*
  - **W (direct path-W inputs):**
    - Amount: AMOUNTS 312, RESULT_LOT_AMOUNTS 364, RESULT_AMOUNT_STEMS, `amount_target` 10265, and
      BT-195 withheld markers whose source is an amount, BT-720 or a statistic.
    - StatedTotal: `stated_total_kind` 8925 (BT-27-Procedure), BT-161/118/1118-NoticeResult and the
      TED totals.
    - LotResult, winners and tenderer refs: `read_results` 7254, RESULT_*_STEMS 9408, OPT-300-Tenderer,
      OPT-301-Tenderer-SubCont, the legacy and sdk-0.1 result readers.
    - Published lot numbers: PUBLISHED_LOT_NO_FIELDS 8839, including BT-137-* and
      DE1-ProcurementProjectLot-ID.
    - Lot titles: TEXTS title entries, because R6 reads the served lot title (canonical.rs:4914), and
      ORIGINAL_LANG_FIELDS, which picks that title's language.
  - **W-ind (indirect):**
    - Winner identity: the ORG name, identifier and country fields. R1, R6 and n_winners read
      organization ids.
    - Every OPT-300/301 role ref. 530-T's role guard (guid_twin.rs:234) decides a GUID-twin group's
      identity before `ExtractedWinners`.
    - Chain membership and version order: BT-04, BT-701, OPP-090, publication and dispatch dates,
      subtype. This is 539's precedent.
  - **nonW:** classifications, dates, nature (BT-23), procedure type, dps, place country, and the
    non-title texts.

  The two touchpoint fields that 576 U2 is adding (uncommitted, in the worktree only) are included as
  W-ind.

**Matching.**
- *Fold semantics* (`intersection.tsv`). An entry keyed by stem matches when the full id or its `stem()`
  (project.rs:9311) equals the key; this is `canonical_name` at 9626. An entry keyed by full id needs
  equality. Prefix and suffix entries match as their names say.
- *The task's generous reading* (`intersection_broad_stem_only.tsv`). `{a, stem(a)}` is matched against
  `{b, stem(b)}`, and the file lists only what this adds. Ids in A that the fold reads for non-W purposes
  are in `nonW_reads_in_A.tsv`. They are not hits.

## 5. Why the 3 code-derived W pairs should leave canonical facts unchanged

This section does not change the verdict.

- **Same canonical name on both sides.** Old and new ids normalise to the same stem (BT-27, BT-271,
  BT-21), so `canonical_name` gives the same name (`estimated_value`, `framework_maximum`, `title`).
- **Same scope.** The scope comes from the section, which is the same Lot section. 577 U2 changes only
  the bound id, not how sections are formed.
- **The one exact read is skipped on DE-1.x.** The only exact-id read of any alias target involved is
  `stated_total_kind`'s "BT-27-Procedure" (8925). `notice_stated_totals` returns before it for every
  eforms-de-1.x notice (8950, `is_de1_profile`).
- **Withheld marks match.** Withheld marks key on `stem`, which is the same on both sides.

This agrees with 577's own reading at 577:151-153 ("map to the same stem … the fold keys by stem and takes
the scope from the section") and with its golden test (b), where `project_apply.snapshot` is unchanged.
Changing the verdict would need a re-decision of W7's rule, for example "code-derived moves whose
normalised fold read differs", which belongs to 551/577's owner. The decision text (section G) says the
golden pin cannot discharge W7, and P1 never runs the new parser.

## 6. Caveats

- **The emulation stands in for running the test.** It is a Python port. It is validated against the
  gated test's exact pins, but the test itself was not run here: no cargo was run, another agent has an
  uncommitted 576 U2 edit in `crates/ingest/src/project.rs`, and cargo is single-runner in this workflow.
- **Python vs Rust parsing.** Predicates are compared as whitespace-stripped strings and as frozensets,
  which is more generous than Rust's ordered `Vec<Pred>` equality. `co_match`'s exclusions are emulated
  textually. The exact pin match shows no divergence on these inventories.
- **Generous tiers.** W-ind is conservative: role refs reach winner identity only through 530-T's role
  guard, and chain fields reach W only through version order. No chain or org id is in A anyway.
- **Withheld markers.** BT-195 declarations whose source is not an amount, BT-720 or a statistic were
  classed nonW. `withheld_source_fields` reads all of them, but the set is looked up only for amount
  stems, BT-720 and BT-759/760.
- **Worktree vs HEAD.** Set B is from HEAD. The worktree differs only by 576 U2's two touchpoint
  literals (`fold_literals_worktree.tsv`), and they hit nothing in A.
- **Shifted line numbers.** The rule's "project.rs ~8866" is now 8925, and canonical_name and stem are
  now 9626 and 9311.
