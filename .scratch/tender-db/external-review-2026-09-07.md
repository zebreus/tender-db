# External review of tenders.zebreus.click, 2026-09-07 — verification record

An external reviewer sent a symptom report (REST API, notice content, read-only SQL on a
throwaway account they deleted afterwards). Five verifiers re-ran every claim against the code
and against production, and each confirmed symptom was traced to the mechanism that produces it
rather than filed as written; a synthesiser then grouped symptoms sharing one cause. Issues
364 (`legacy-ojs-closure-welds-unrelated-procurements`), 365 (`identifier-catch-all-any-string-is-a-merge-key`), 366 (`head-columns-elect-max-over-unflagged-facts`), 367 (`notice-instants-resolved-once-and-flattened`), 368 (`unmapped-source-vocabulary-dropped-silently`), 369 (`procedure-key-accepted-unchecked`), 370 (`served-claims-nothing-re-derives`), 371 (`currency-has-no-reachable-leg`) came out of it.

This file keeps the other half of the record: the claims that did NOT become issues, so they are
not re-litigated. Two of the reviewer's three headline diagnoses were wrong about the mechanism
while right about the symptom, which is why the causes were re-derived instead of trusted.
