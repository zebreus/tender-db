## 5. Methodologies (what actually worked — the session's real playbook)

1. **The diagnose→fix→reprocess loop** (the star): sample stratified members from
   quarantine via bounded /v1/sql reads → extract real bytes from archive tars
   (one `tar -xf` pass per tar) → run through the EXACT prod parse path
   (dispatch→parse_payload harness, `crates/ingest/examples/diag39.rs` pattern)
   → **minimize** (delete one suspect element → PARSED proves single cause) →
   implement minimal gap-fill/carve-out fixes in the established idioms
   (`insert_extra` gap_only, EXTRA table, Branch::existing no-create) →
   **falsify** every test against stashed fixes (must reproduce the exact
   diagnosed error) + negative controls (unknown constructs still quarantine) →
   gate → deploy → blanket reprocess → **measure the residue honestly**.
   A minimization proof is per-SAMPLE; population claims are sized only by
   running the fix.
2. **Verification discipline** (the whole of [[verification-input-discipline]] —
   READ IT; it's the distilled cost of ~30 instrument bugs): measure the
   load-bearing artifact, not a correlate; no verdict line = FAILED, not pending;
   never retry a 408 (bounds the wait, not the work); scope refuting arms to the
   intervention; pre-registration protects against fitting, not wrongness;
   check the RECORD before instrumenting the system; a reason string is a
   symptom (four populations hid under one label, twice); a predicate verified
   over corpus X is silent about X's boundary; guards must be proven
   DISCRIMINATING (a non-trivial split), not merely fired; prefer structure
   (CHECK/UNIQUE/FK) over runtime guards.
3. **Guarded destructive ops**: exact `expect` + `expect_gaps` (re-aim, never
   disarm; a missing argument must be the SAFE reading); dry-run first;
   reversible writes (skipped_reason tags); independent post-execute assertion
   by a second seat.
4. **Two-seat review**: nearly every error was caught by the OTHER seat, never
   self-review. When teammates are down, spawn subagents with falsification
   requirements written into the brief (and require FULL SHAs from
   `git rev-parse` — a hand-transcribed SHA dropped a character once).
5. **Honest records**: results become committed artifacts immediately (a result
   in scrollback has a half-life); corrections chase conclusions, not just
   sentences; unresolved work never sits under a "Resolved" heading; label
   mixed-provenance data.
